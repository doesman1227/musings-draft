2026.06.20AI

AIの仕組みを、一気に地図にした日。

LLMから始めて、Transformer・Attention・Token・Embedding・Vector Database・RAG・MCP・Function Calling・AIエージェントまで。バラバラだった用語が、一本の線でつながった。理解とは、点を線にすることなのかもしれない。

LLM（Large Language Model）

概要

LLM（Large Language Model：大規模言語モデル）は、大量の文章を学習し、人間のような自然な文章を理解・生成できるAIモデルである。

ChatGPTやGemini、Claudeなど、多くの生成AIの頭脳として利用されている。

特徴

  • 自然言語を理解する
  • 文章を生成する
  • 推論ができる
  • プログラムを書く
  • 要約・翻訳ができる

代表的なLLM

  • ChatGPT
  • Gemini
  • Claude

関連ノート

  • AI
  • Transformer
  • Token
  • Attention
  • Embedding

自分の考え

生成AIの中心技術。 AIを理解する上で最初に理解すべき概念。

Transformer

概要

Transformerは、現在のLLMの基盤となるニューラルネットワークアーキテクチャである。

2017年にGoogleが発表した 「Attention Is All You Need」 によって提案された。

特徴

  • Attentionを利用する
  • 並列処理が得意
  • 長文を扱える
  • 学習効率が高い

関連ノート

  • Attention
  • LLM
  • Token

自分の考え

Transformerの登場によって生成AIは大きく進化した。

Attention

概要

Attentionとは、「文章のどこに注目すべきか」を判断する仕組みである。

人間が文章を読むときと同じように、 重要な単語へ重点を置く。

役割

  • 文脈理解
  • 単語同士の関係を理解
  • 長文理解

関連

  • Transformer
  • LLM
  • Token

自分の考え

Transformerを理解するために最重要の概念。

Token

概要

Tokenとは、LLMが文章を処理するときの最小単位である。

単語や文字の一部がTokenになる。

Tokenの例

こんにちは

↓

こん

にち

は

のように分割されることもある。

Tokenが重要な理由

  • AIはToken単位で考える
  • 利用料金にも影響する
  • コンテキスト長にも影響する

関連

  • LLM
  • Transformer
  • Embedding

自分の考え

AIと会話するときは、文字数ではなくTokenで処理されていることを意識すると理解が深まる。

Embedding

概要

Embeddingとは、文章や単語をAIが理解できる数値（ベクトル）へ変換する技術である。

AIは文字そのものではなく、意味の近さを数値として扱っている。

役割

  • 意味を数値化する
  • 類似した文章を探せる
  • 検索性能を向上させる

イメージ

犬

↓

(0.82, -0.14, 0.65, …)

猫

↓

(0.80, -0.11, 0.67, …)

犬と猫は近い位置になる。

関連

  • LLM
  • Vector Database
  • RAG

自分の考え

AIは単語ではなく「意味」を扱っている点が面白い。

Vector Database

概要

Embeddingされたデータを保存し、意味の近い情報を高速に検索するデータベース。

役割

  • Embeddingを保存する
  • 類似検索を行う
  • RAGの基盤となる

代表例

  • Pinecone
  • Weaviate
  • Chroma
  • FAISS

関連

  • Embedding
  • RAG

自分の考え

Google検索がキーワード検索なら、Vector Databaseは意味検索と言える。

RAG（Retrieval-Augmented Generation）

概要

RAGとは、LLMが回答を生成する前に外部の知識を検索し、その情報を利用して回答を生成する仕組みである。

流れ

質問

↓

Embedding

↓

Vector Database

↓

関連情報取得

↓

LLM

↓

回答生成

メリット

  • 最新情報を扱える
  • ハルシネーションを減らせる
  • 社内文書を利用できる

関連

  • Embedding
  • Vector Database
  • LLM
  • AIエージェント

自分の考え

AI単体よりも、知識と組み合わせることで実用性が大きく向上する。

MCP（Model Context Protocol）

概要

MCPは、AIが外部ツールやデータと安全かつ統一的に接続するための共通プロトコルである。

異なるサービスとの連携を標準化し、AIエージェントを構築しやすくする。

役割

  • ツール接続の標準化
  • コンテキスト共有
  • AIエージェントの基盤

関連

  • Function Calling
  • AIエージェント

自分の考え

AI版のUSBのような存在。さまざまなツールを同じ方法で接続できる未来を支える技術。

Function Calling

概要

Function Callingとは、LLMが必要に応じて外部ツールやAPIを呼び出す仕組みである。

できること

  • 天気取得
  • メール送信
  • データベース検索
  • カレンダー登録
  • Python実行

関連

  • AIエージェント
  • MCP

自分の考え

AIが「答える存在」から「実行する存在」へ進化する重要な技術。

AIエージェント

概要

AIエージェントとは、LLM（大規模言語モデル）に「考える」「記憶する」「ツールを使う」「実行する」能力を組み合わせたシステムである。

従来のチャットAIが質問に答えることを主な役割としていたのに対し、AIエージェントは目標を達成するために複数の処理を自律的に実行できる。

AIエージェントを構成する要素

1. 頭脳（Brain）

中心となるLLM。

例

  • ChatGPT
  • Gemini
  • Claude

役割

  • 考える
  • 推論する
  • 文章を生成する

2. 記憶（Memory）

過去の会話や知識を保持する。

短期記憶

  • 今回の会話

長期記憶

  • Obsidian
  • Vector Database
  • NotebookLM

3. ツール（Tools）

LLMだけでは実行できない処理を行う。

例

  • Web検索
  • Python実行
  • メール送信
  • カレンダー操作
  • GitHub操作
  • API呼び出し

4. 実行（Action）

考えるだけではなく行動する。

例

  • ファイル作成
  • スケジュール登録
  • ブログ記事作成
  • PowerPoint作成
  • データ分析

AIエージェントの処理フロー

ユーザー
    │
    ▼
目標を受け取る
    │
    ▼
LLMが考える
    │
    ▼
必要なツールを判断
    │
    ▼
ツールを実行
    │
    ▼
結果を評価
    │
    ▼
必要なら再度考える
    │
    ▼
ユーザーへ回答

AIエージェントとチャットAIの違い

|項目|チャットAI|AIエージェント| |---|---|---| |目的|質問に答える|目標を達成する| |ツール利用|限定的|積極的に利用| |複数ステップ|苦手|得意| |記憶|少ない|長期記憶を持てる| |自律性|低い|高い|

Doesman Second Brainとの関係

このVaultでは、ChatGPT・Gemini・NotebookLMなどのAIを「知識を生み出すパートナー」として利用し、最終的な知識はObsidianへ蓄積する。

役割分担は以下の通り。

  • AI：考える・比較する・要約する・提案する
  • Obsidian：知識を保存・整理・リンクする
  • 自分：理解する・判断する・価値を生み出す

この仕組みにより、「知識の蓄積」と「AIによる思考支援」を両立できる。

自分の考え

AIエージェントは、人間の代わりになる存在ではなく、人間の思考を拡張する存在だと考えている。

重要なのはAIに任せることではなく、人間が問いを立て、AIと対話しながら知識を育てることである。

Doesman Second Brainは、その知識を蓄積し続けるための基盤になる。
